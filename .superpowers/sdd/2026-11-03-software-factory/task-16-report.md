## Implementation and reviewed scope

- `src/broker/capabilities.ts`: 32-byte random capability identity plus HMAC-SHA256, encoded as a single canonical 86-character base64url token. Only immutable capability identity/scope/operation/expiry records are persisted; raw bearer values are not stored. Inject a protected persistent signing key of at least 32 bytes (no production default). Token TTL defaults to five minutes, maximum thirty minutes; the fixed registered actor scope expires within 24 hours and remains unusable without its current live lease. Every issuance/use checks current actual reservation, latest task attempt, latest exclusive repository fence, live lease, repository/factory control, pinned recipe hash/readiness/activity/tag, exact grant registration/current grants/expiry, target ownership and positive operation allowlist. JSON scope must match authenticated scope and never creates authority. Revocation persists. Fresh final tokens have `result.submit` only; start tokens have `native.start` only.
- `src/storage/broker.ts`, migration `005_broker.sql`, minimal FactoryStore/TaskStorage integration: use the same actual factory SQLite transaction/actor/task/lifecycle domain. `store.broker.transaction(callback)` rejects promises; local authorization, mutations and immutable receipts commit together. Capability records, result proposals, artifact metadata and native-write claims are durable. Existing task CRUD/finding dedup/revisions remain authoritative. Root-approved `FactoryStore.createGeneratedTask(spec,actor,key)` preserves permitted worker goal/acceptance/context content through existing task validation/insertion/child linking; broker generates IDs and inherits recipe/tag/repository/parent/owner/provider/finish/required/tools/skills. It rejects escalation rather than ignoring it.
- `src/broker/operations.ts`: route-independent authorization/execution. Generated children are actual store records. Results validate real scoped children and persist an immutable structured proposal; they never set completed status or C8 verification. Artifact operations register/read metadata only (no path-based file access). Native start is reconstructed from reservation, exact supplied sensitive fields are compared, and one native writer is claimed per attempt/fence before dispatch. Native continuation requires actual persisted identity, quiescence, a fresh fence and the trusted C4/E6 continuation port.
- Native intents remain pending/unknown across transport loss/process restart. Existing claims invoke only `native.reconcile` and never resend; different keys/payloads cannot acquire a second writer. Known results are immutable. Current authority is rechecked after asynchronous profile work and before publishing native completion. Exceptions after a possible effect retain the claim. There is no worker operation to clear uncertain claims; trusted lifecycle reconciliation/quiescence is required before advancing authority.
- Attention uses actual C4 persistence/events. `LifecycleUpdate.attention.source?: 'owner'|'workflow'` defaults to owner for existing C4 callers. Broker blocked/error requests use authoritative workflow provenance and server-generated ID/task/attempt/repository/time/status/revision. Input/approval requests require trusted `pendingNativeInput(attemptId)` returning actual persisted native identity plus current `NativeInput`; prompt/schema/nativeInputId are reconstructed and kind becomes `input`, so actual C4 `queueLifecycleReply` works. Missing correlation fails with actionable `attention_input_unsupported`; no unanswerable form is created.
- `src/broker/server.ts`: `startWorkerBroker({broker}) -> Promise<WorkerBroker>`, with `handle(BrokerHttpRequest) -> Promise<BrokerHttpResponse>`. It exposes only the eleven positive worker routes and exact per-route logical operation/target. No browser/admin/owner management routes. Shared E1 codec handles all logical request and success/error replies exactly once, bounded by its exported wire limits. GET derives scope from the token. Logical `idempotencyKey` is the sole mutation key; E1 starter requests do not need a separate header. Local results are checked for encodability before committing.
- `src/broker/bridge.ts`: actual cross-platform Docker-exec streaming production transport, not a fixture facade. `startPrivateBrokerBridge({installation,kestra,broker,streaming?})` creates/adopts a frozen pinned Node relay on exactly `kestra.brokerNetwork`, alias `sf-broker`, port 8080. No published ports, host mounts, Unix sockets, credentials on argv, Docker socket, or worker network membership. Explicit image/command/entrypoint/environment/user/caps/namespaces/mounts/network/resource/ownership inspection precedes adoption and every request. Engine-network peers are restricted to the actual E2 engine/transport and this trusted relay. Docker leaves NetworkID empty before first start: verify exact selected owned network/alias before starting, then require its assigned effective ID. A focused regression covers this actual daemon behavior and foreign-ID rejection.
- The relay has bounded newline frames, unique request IDs, eight in-flight requests maximum, body/frame/header bounds, backpressure, timeouts and a readiness handshake. EOF/malformed frames close the session; host durable intents preserve unknown outcomes. `ProcessStreamingDocker(executable='docker')` uses shell:false, stdin/stdout and drains stderr without credential logging. E7 can inject its known Docker executable. The production path was exercised with Windows Docker from WSL without changing any global settings or relying on the broken host-bind bridge.
- `src/broker/authority.ts`: actual E2 `KestraAuthority` implementation from current store. `createKestraAuthority({broker,store})` reconstructs start/final-result requests and fresh operation-limited caps, rejects reserved sf_ inputs, compares exact pinned recipe/fence and verifies actual workflow/native/retry lineage for continuation. `WorkflowStart.scopeId` MUST be the actual reservation ID. E2 shared opaque codec and continuation journal remain authoritative.
- `src/isolation/{profiles,verify,docker}.ts`: no import of the old always-blocked probe stub and no readiness minted from historical fixtures. `createProfileVerifier({profiles,now?}).requireVerifiedProfile(start)` validates canonical real paths (including symlink and dot-prefix containment), exact effective image/mounts/networks/tool/credential/egress authority, protected metadata, nonce-bound active denial canaries and unchanged runtime/process settings before/after the challenge. Evidence binds actual start, runtime/process/image and inspected settings. `requireVerifiedProfile` default registry is empty and truthfully rejects unsupported combinations.
- `createDockerNativeBoundary({docker,containerId,runtimeOwnerId,image,networks,protectedPaths,tools})` performs actual Docker/image/network inspection, nonroot/read-only/drop-all/no-new-privileges/private namespace/no extra mounts/network/device/host-egress checks, and active fixed Node open/access denial canaries with no secret contents read. `tools: NativeToolBoundary` is mandatory: Docker flags alone cannot prove native/client-side external-tool, credential, metadata and alternate-egress restrictions. That producer must inspect the actual paired owner/tools and execute all denial checks through their real path. Fixture values are not production defaults.
- Protocol generator/OpenAPI now narrow each routed logical operation inside the documented `sf-base64url-json-v1` envelope; responses/errors also document the opaque transport. Browser/owner routes retain their contracts. Synthetic downgrade fixture now removes v5 tables before recreating v2; schema version assertion advances to 5.
